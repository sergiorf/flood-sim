## What changed

### FS-014 - hot-path cleanup

The simulation hot path was cleaned up in `core/src/simulation.cpp` without
changing routing semantics:

- per-step `delta` storage is now reused through a thread-local scratch buffer
- per-cell lower-neighbor collection now uses fixed `std::array<Neighbor, 4>`
  storage instead of dynamic allocation
- `rows` and `cols` are cached locally inside `step()`

Build and tests passed after this change.

## What the clipping change means

The important design point is:

- clipping is part of the terrain-ingestion boundary, not a special-case
  behavior inside the example binary

That means later Phase 2 scenario work can request smaller terrain windows while
still receiving the same validated `TerrainRaster` contract used everywhere
else.

Semantics to remember:

- indexing inside the returned `TerrainRaster` is local to the clipped result
- `rows` and `cols` describe the clipped raster, not the original source raster
- `origin_x_m` and `origin_y_m` shift to the clipped top-left cell so exported
  outputs stay map-aligned
- nodata handling is unchanged: invalid cells remain in the raster shape and are
  excluded through `valid_cell_mask`
